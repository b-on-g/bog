## Как устроен старый сборщик, минимум для старта

1. `$mol_build.root( dir ).bundle([ path, bundle ])` собирает пакет. Без имени бандла собирает всё: `deps.json`, `css`, `js`, `mjs`, `test.js`, `d.ts`, `view.tree`, `locale`, `audit.js`, потом `package.json`, `manifest.json`, `readme`, `index.html`, `test.html`, `deploy`.
2. Зависимости файла ищет `$mol_build.dependors[ ext ]`: регулярки по тексту, свои для `ts`, `js`, `css`, `view.tree`, `meta.tree`, `glsl`. Отступ строки задаёт приоритет.
3. Исходники других форматов превращаются в ts отдельными методами: `viewTreeTranspile`, `glslTranspile`, `metaTreeTranspile` и так далее.
4. `modEnsure( path )` клонирует отсутствующие пакеты по `pack` из `*.meta.tree` и делает `git pull`.
5. Сервер (`server.node.ts`) по URL `/mod/-/web.js` вызывает `bundle`, по вебсокету сообщает странице, что пора перезагрузиться.

Отладка: `node --inspect-brk mol/build/-/node.js path/to/mod`, конфигурация есть в `.vscode/launch.json` стенда.

## Боли старого сборщика, от простого к сложному

Каждый пункт это отдельный маленький PR в `hyoo-ru/mam_mol`. Коммит `$mol_build: …` или `$mol_build_server: …`.

### 1. Дев-сервер умирает от EOF на stdin (S) — PR [#900](https://github.com/hyoo-ru/mam_mol/pull/900)

`mol/build/server/server.node.ts`, метод `repl()`: `.on( 'close', () => process.exit(0) )`. Если stdin не терминал (CI, docker, запуск в фоне, `mam &`), stdin сразу закрыт и сервер выходит. Сейчас это обходится костылём `sleep | mam`.

Что сделать: при `!process.stdin.isTTY` не создавать readline. В новом сборщике это уже сделано: `mam/server/repl/repl.node.ts`.

Проверка: `npx mam < /dev/null &`, сервер должен остаться жив и отвечать на `curl localhost:9080/`.

### 2. npm-зависимости проекта видны только в бандле (S)

Сейчас `npm install` при автоустановке кладёт пакет в корневой `package.json` MAM, а в репозитории проекта (`bog/myapp/`) о зависимости не знает никто, кроме `-/package.json` бандла.

Что сделать: после `bundlePackageJSON` дописывать используемые пакеты в `package.json` корня git-репозитория пака: поднимаемся от модуля до папки с `.git`, но не выше корня MAM. Версию берём из `node_modules/<pkg>/package.json` как `^x.y.z`. Существующие поля не трогаем, встроенные модули (`$node_internal_check`) пропускаем, пишем файл только при изменении, иначе вотчер зациклится. Готовая реализация для нового сборщика: `mam/bundle/bundle_npm_deps.ts` в #65.

Проверка: пак с `.git` и `$node.yaml`, после сборки в его `package.json` появился `yaml`, повторная сборка файл не трогает.

### 3. Мелочи test.html (S)

Из нового сборщика (`mam/bundle/bundle_test_html.ts`, `mam/server/server.node.ts`):
- кэш-бастинг `web.js?v=<версия>`, чтобы браузер не брал старый бандл;
- если у пакета нет `index.html`, корневой вид ищется по `*.view.tree` вверх по папкам.

Проверка: открыть `test.html` модуля без `index.html`, поправить код, обновить страницу, бандл должен быть свежий.

### 4. Выход за корень в сервере (S, сначала проверить)

`server.node.ts` резолвит `req.path` от корня без проверки. Нужно проверить, отдаётся ли что-то по `curl --path-as-is 'localhost:9080/../'` и по `%2e%2e`. Если отдаётся, добавить проверку, как в новом: `relate()` не должен начинаться с `..`.

### 5. Типизированный `$npm` (M)

Сейчас `$node.yaml` работает, а типы генерируются в `-node/deps.d.ts` (`build.node.ts`, около строки 398) только для node-среза. В вебе пакет подтягивается целиком.

Шаги:
1. `interface $npm` и `$npm` на вебе и ноде (`npm/npm*.ts` из #65), `deps.d.ts` для обоих срезов. Проверка: `$npm['yaml'].parse` даёт автокомплит, `$npm['nope']` даёт ошибку типов.
2. Веб-чанк через esbuild вместо склейки CommonJS (`mam/convert/convert_npm.ts`).
3. Tree-shaking по использованным членам. Нужен разбор TS AST (`mam/source/source_ts_npm.ts`), а старый ищет зависимости регулярками, так что это самый тяжёлый шаг. Решать после первых двух.

## Архитектура: потом

Что даёт новая: плагины без форка мола (свой лоадер, конвертер или бандлер через наследника `$mam_root`), цепочки превращений (gql → ts → js), мелкие куски с юнит-тестами, бандлеры просят файлы по типу через `slice.files_of()`. Скорости больше не даёт: Стас перенёс ускорение в старый.

Как продавать: через GQL и OpenAPI (#54). В старом сборщике кодогена нет и без правки мола его не добавить, в новом это два класса. Если Дима согласен, стопка #59–#65 готова, а #54 ложится восьмым PR.

## Грабли, на которые уже наступили

- `$mol_run.spawn` внутри мемо бандла даёт бесконечный цикл: фибра перезапускается, бандл пишется заново. Тесты из бандла запускать через `spawnSync`.
- Старый сборщик ищет зависимости даже в комментариях и строках: JSDoc с `$node.x` и строка `import( "lazy/file" )` в фикстуре ставили пакеты `x` и `lazy`.
- Виртуальный файл (`text( …, 'virt' )`) живёт, пока его кто-то читает. Если единственный читатель упал, ячейку сметает, и следующее чтение идёт с диска.
- На маке нет `timeout`, долгие сборки гонять со сторожем.
